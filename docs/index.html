01/ Introduction

The Problem We're Solving

Wi-Fi 7 introduces Multi-Link Operation (MLO), allowing devices to simultaneously use multiple wireless bands — 2.4 GHz, 5 GHz, and 6 GHz — for dramatically improved throughput and reliability. But this new coordination logic is also a new attack surface.

Current research is fragmented: one side optimises MLO performance; the other studies legacy wireless security threats. Protocol anomalies like backoff compensation and free-ride behaviour are treated as performance quirks — not deliberate exploits.

This project bridges that gap by building a security-focused Network Digital Twin that replicates realistic MLO behaviour, injects adversarial scenarios, and uses a GCN-based detector to classify attacks in real time.

02/ Threat Model

MLO Attack Vectors

⚡

Backoff Manipulation & Free-Ride

A malicious device manipulates internal backoff counters to gain channel access repeatedly without proper waiting — effectively skipping the queue and starving legitimate devices.

Critical
🔗

Primary-Link Denial of Service

By targeting the primary link which handles control flow and legacy compatibility, an attacker can create a chokepoint that collapses the entire multi-link session.

Critical
📡

Packet Steering Exploitation

If an attacker falsifies link metrics or biases the scheduling logic, the steering system routes traffic suboptimally — degrading QoS for all legitimate devices on the network.

High
🎯

Spoofed CSI & Beam Hijacking

By injecting false Channel State Information, adversaries can redirect beamforming targets — intercepting or degrading directional transmissions with minimal detection risk.

High
🔀

Multi-Link Association Hijack

Weaknesses in the association handshake across multiple links create windows for session hijacking or man-in-the-middle positioning across all bands simultaneously.

High
🤖

ML Scheduler Adversarial Attacks

MLO increasingly uses ML-based scheduling. Adversarial inputs crafted to exploit model blind spots can bias link allocation decisions in favour of the attacker.

High
03/ System Architecture

The 6-Stage Pipeline

Stage 01
NS-3 Simulation
sim/ns3/scenario/

Simulates real Wi-Fi 7 MLO behaviour — generating throughput, jitter, backoff slots, and multi-link events. Outputs a raw telemetry.jsonl file per experiment.

Stage 02
Telemetry Exporter
telemetry/exporters/ns3_file_exporter

Watches simulation output, parses the JSON stream line-by-line, and publishes events to the Redpanda/Kafka topic wifi7.telemetry.v0_1. Duplicate publishing is prevented via .exporter_state.

Stage 03
Message Broker
Redpanda / Apache Kafka

Orchestrates the entire data flow as a central message bus between the exporter, harmonizer, and windowizer — ensuring decoupled, fault-tolerant communication across all stages.

Stage 04
Harmonizer
telemetry/harmonizer → TimescaleDB

Consumes raw events from Kafka, normalises data, and streams it into TimescaleDB's metrics table — providing persistent historical telemetry for Grafana's 38 unified dashboard panels.

Stage 05
Windowizer
security/detector/windowizer → wifi7.ml.windowed_features.v1

Converts cumulative counters into point-in-time deltas and buffers them into exactly 256-event sliding windows, then publishes 13-feature vectors to the ML topic for GCN consumption.

Stage 06
GCN Detector
twin/gnn/detector → gcn_predictions

Subscribes to windowed features, loads the active versioned GCN model, and performs low-latency inference — classifying segments as Normal (0) or Attack (1). Results surface via the live React dashboard on port 8888.

04/ ML Model

Graph Convolutional Network Architecture

📊
Input Node Features
13–16 features per node (throughput, delay, backoff slots…)
🔗
Temporal Chain Graph
256 nodes per graph · Bidirectional edges t ↔ t+1
🧠
GCNConv Layer 1
Projects to 64-dim hidden space · BatchNorm · ReLU
🔄
GCNConv Layer 2 + Skip Connection
Message passing · Residual h = h + h_new · Dropout 30%
🔀
Global Graph Pooling
Mean (default) · Max · Concat strategies
⚖️
MLP Classifier Head
Linear(64,32) → ReLU → Dropout → Linear(32,2) → Softmax
🎯
Binary Output
Class 0: Normal · Class 1: Attack · Threshold P > 0.5

Why Temporal Chain Graphs?

Unlike tabular ML, the GCN explicitly models the sequential relationship between time windows. Each 256-event segment becomes a node, and bidirectional edges allow the model to understand local temporal context — crucial for detecting stealthy, gradual backoff drift.

Oversmoothing Mitigation

Deep GCNs tend to blur node representations into indistinguishable averages. This architecture fights that with skip/residual connections (h = h + h_new) preserving individual node identity while still aggregating neighbour information.

Training Configuration

Adam optimiser · LR 0.001 · L2 weight decay 1e-4 · ReduceLROnPlateau on validation F1 · Batch size 32 graphs (8,192 nodes). Class imbalance addressed with weighted loss to ensure anomaly detection sensitivity.

Inference Engine

Ultra-fast offline feature scaling via saved scaler.json. Softmax confidence scores routed through Kafka directly to TimescaleDB's gcn_predictions table for sub-second attack flagging.

Model Registry & Versioning

Production models versioned under twin/registry/gcn/current. New versions validated with make gcn-evaluate MODEL=v2.0.0 against 284 labelled scenarios, producing structured JSON metrics: F1, Recall, Accuracy.

05/ Quality Assurance

Testing Infrastructure

Unit

Windowizer Tests

  • test_aggregator.py — Verifies 256-slot windows accumulate data correctly without overflow or loss
  • test_delta.py — Ensures cumulative metrics convert to accurate frame-to-frame deltas
  • test_segment.py — Validates segment boundary creation logic
Unit

GCN Detector Tests

  • test_graph_builder.py — Validates adjacency matrix and edge generation for correct graph topology
  • test_inference.py — Verifies classification logic without tensor shape errors
  • test_model_loader.py — Ensures correct loading and swapping of .pt weight files from registry
E2E

End-to-End Security Testing

  • Full pipeline validation: NS-3 → Kafka → Windowizer → GCN → TimescaleDB assertion
  • Normal vs backoff-bias attack scenarios with formal throughput measurement under adversarial load
  • Documented in WP8-PHASE4-E2E-TEST-ANALYSIS.md and WP8-LIVE-TEST-FINAL-SUMMARY.md

Model Evaluation

  • 284-scenario static validation dataset for reproducible benchmarking
  • Structured JSON output: F1 Score, Recall, Accuracy per model version
